### V-1 翻页动画矩阵——对标 Wenku8_Flutter 六效果（2026-11-25 依参考源码定稿，替换原"双缓冲快照+3D 折影"方案）

**参考实现**：`github.com/mikufoxxx/Wenku8_Flutter`（用户手机在用的安卓版；本地克隆 `F:\tmp\wenku8_flutter`）
核心三文件：`lib/reader_sheet_motion.dart`（动画渲染，299 行）/ `lib/reader_paged_view.dart`（编排，2007 行）/ `lib/reader_preferences.dart`（效果枚举 ReaderPageEffect）。

**四条核心原理**（源码实证）：
1. **双 live 叶片，零截图**：翻页瞬间新旧两页同时保留（各裹 RepaintBoundary），动画=对 live 页施加**合成层**操作（ClipPathLayer/TransformLayer/OpacityLayer）——不做 DOM 克隆、不逐帧截图。源码注释原话："A fold is two complementary clips and a paper crease, not two fading text planes or a screenshot captured on every frame."
2. **单一进度源**：全局唯一 `progress∈[0,1]` + `direction(±1)` 驱动所有效果；progress 是滚动手势的纯函数（`_scrubTurn`：拖动位移/页宽 → 拖动即预览，松手滚动物理收尾到 0 或 1）——**天然可抢占**（连按/反向重拖无需 clearTimeout 补丁，progress 永远由当前手势重算）
3. **效果=同一 progress 下的纯画法差异**（见下表，可整组抄参数）
4. **章界预排版（edge slot）**：相邻章首页提前排版挂在 PageView 轨道两侧边缘槽位（itemCount=本章页数+2），跨章动画翻的是**真实下一章内容**，动画完成后帧回调才真正换章

**六效果画法**（数值全为相对页宽 w、包络 e=sin(π·progress)）：
| 效果 | 画法 |
|---|---|
| 无动画 | 直接跳变 |
| 平移 | 轨道原生滚动：新旧两页同排随位移整体平移（无特效层，PageView 自带） |
| 覆盖 | 新页携**不透明纸底**自边缘滑入压住静止旧页（位移 = w·(1-t)）；前缘软阴影带宽 min(22px, 5.5%w)、峰值 alpha 0.16·e，只投在下方旧页露出侧 |
| 渐隐 | 交叉淡化（旧 1-t / 新 t）；**每叶背后先铺不透明纸底**，防两页文字透叠重影 |
| 纸页翻动 | 两互补**弧形 clip**（三次贝塞尔边缘）沿移动折痕分界（折痕 x=w·(1-t)）；折弯 bend≤min(24px,4.5%w)、折页宽 fold≤min(28px,6.5%w) 均乘 e；折痕阴影带 spread≤min(26px,7%w) alpha≤0.3·e；折页高光=三段渐变（暗→亮→纸色）模拟纸背受光。**无 WebGL/着色器/3D 变换**——纯 2D clip+渐变 |
| 段落接续 | 段落级错峰平移（该 App 默认效果；本库**可选低优先级**） |

**方案改定（2026-11-25 晚，动手前审计 + 最小实验后；取代下方原「落地架构」）**

GhostView 双 rendition 路线作废，改为 **View Transitions 快照双叶**（原落地架构保留在下仅供回溯）。

审计结论——为什么不再修 GhostView（均有源码依据）：
1. 章内「一页」不是独立元素：整章是一张横向多栏长 iframe，「翻页」只是外层 `.epub-container.scrollLeft` 挪一栏（epub.js `managers/default/index.js` 的 next/prev → `scrollBy(delta)`）；跨章才 `clear()` **同步销毁旧 iframe 再建新的**，中间没有新旧同框的窗口——跨章闪白是结构性的
2. GhostView 每次翻页都要重建第二 rendition（display 锚点 + 步进 = 多渲染一整章）；每建一个 Rendition 还往共享的 `spine.hooks.content` 多挂一条 `injectIdentifier`（destroy 不注销），越翻越慢
3. 纸面没有实色可取：浅色四档 iframe body 透明，纸面是半透明渐变叠壳底色与两团光斑；dark / ink-dark 的 `--wr-paper` 是 6% 白。Ghost 的「不透明纸底」与真实纸面必然有色差，撤 ghost 那一帧会跳色（根因 B 修不干净）
4. 高亮是宿主侧独立 SVG 层（marks-pane），按 rendition 存——ghost 新叶没有高亮，提交瞬间高亮才闪现
5. 代码里 8 处假定容器内只有一个 iframe（`querySelector("iframe")` / 第一个 `.epub-container`），第二个 rendition 一挂就可能指错
6. 一个 ghost 只能预热一个方向——根因 C 是结构性的，不是预热不足

新方案：
- **机制**：翻页瞬间 `document.startViewTransition(提交)`——浏览器先对「叶片」（正文 + 页码徽标）拍旧态快照，执行提交，再拍新态快照；效果 = 对两张快照（及叶片内的遮罩条）施加的 WAAPI 关键帧（纯函数 `turnKeyframes` 等距采样 17 帧，帧间线性）。卡片、底色、栏不参与捕获，保持实时不动
- **三处根因如何消失**：A——只有一张叶片，不存在嵌套；B——快照就是真实页面的像素，不需要纸色；C——没有「就绪 / 未就绪」两套路径，章内 / 跨章 / 正反向走同一条管线
- **附带根治跨章闪白**：DOM 更新期间旧页快照一直盖着，epub.js「先销毁再重建」的空窗不再露白；「无动画」同样受益（旧页停住 → 新章就绪后直接换）
- **与参考实现一致**：Wenku8_Flutter 的平移 / 覆盖 / 渐隐是双 live 叶片，而**纸页翻动本身就是「每面一张纹理快照」**（`reader_spine_turn.dart`：`SnapshotWidget`，注释 "Each visible face uses one texture-backed snapshot per turn"）；它否掉的只是逐帧截图
- **实测边界**（独立 Chrome 158，与本机 WebView2 运行时 158 同版本；回归工具 `tools/cdp/verify-turn.mjs`）：
  1. DOM 更新回调期间浏览器不产帧、`requestAnimationFrame` 冻结（回调里 await rAF 直接超时）；`setTimeout` / Promise / 强制布局照常 → 回调里不能走 rendition 队列（rAF 驱动），改为直接调 `manager.next()/prev()`（= `Rendition.next` 去掉队列包装），位置上报挪到回调外；跨章新视图「主题注入后重新量宽」原本靠 ResizeObserver → rAF，回调里改为同步调 `contents.resizeCheck()`
  2. 过渡期间点击 / 滚轮默认被遮罩吞掉（命中目标变成 `html`）；`::view-transition { pointer-events: none }` 后热区点击与滚轮照常到达
  3. 被抢占的旧过渡若不取消其动画，新过渡的 finished 会拖到旧动画自然结束才 resolve → 结束 / 抢占时一律 cancel
  4. 更新阶段被打断时 `ready` 会 reject → 等 `updateCallbackDone` 保证提交完成再收尾
  5. 需要 Chromium ≥ 111；不支持或窗口不可见（不产帧）时回落 v3.1.8 路径
- **连按语义**：队列每次按键恰好一页；动画期间再翻 → 打断当前动画直接续下一页（此时新态已捕获，不会露出未就绪的页面）；队列有积压 → 快进（只遮罩不播动画），队尾那次才播
- **时序**：按键 → 下一帧捕获旧态 → 提交（章内同步滚动；跨章渲染新章，旧页快照全程盖着）→ 下一帧捕获新态 → 动画。比 GhostView 多约两帧起步延迟，换掉的是上面六条结构性问题
- **代价**：折页几何无法照抄——参考仓库当前提交引用的 `reader_paper_geometry.dart` 在上游不存在（404）；按本节画法描述实现，逐帧截图验收

**已知缺陷（2026-11-25 用户在 dev 实测，速度拉到 600ms 时最明显；用户裁定整体排到 V-3 之后的动画阶段修）**
- 现象：①五种效果看起来一样、看不清细节 ②闪烁 ③与之前的"先画完再微幅滑入"重叠出现
- 根因 A（读代码已确认，`reader.ts` buildGhost）：新叶 GhostView 被 `appendChild` 到 `opts.container`——而 `opts.container` 正是动画里的旧叶 `oldLeaf`。给旧叶做的平移 / clip-path / opacity 会连带作用到作为其子节点的新叶：平移=新叶以两倍速度掠过后飞出屏幕，渐隐=整页淡到空白，纸页=新叶被旧叶的裁剪一起裁掉。每种效果都退化成"旧页消失 → 两页都不在屏上 → 提交后硬跳"，所以分不出区别、且必然闪一下（现象①②）。**修法：新叶挂到 `.wr-reader-paper`（旧叶的父级）做旧叶的兄弟节点**
- 根因 B（读代码已确认）：新叶底色用了 `var(--wr-paper)`，该 token 在「夜间」「墨夜」是 6% 不透明的半透明色 → 新叶近乎全透明，两页文字透叠（现象③的"重叠"之一）。**修法：底色改用不透明纸面实色**
- 根因 C：GhostView 未就绪（首次翻页冷构建、往回翻——预热只备了前进方向）时落到旧微幅动画兜底，与全幅动画混出（现象③）。**修法：动画阶段统一处理（预热双向 / 手势驱动后 progress 单一来源）**
- **教训：视觉功能的验收必须看画面（逐帧截图/录屏），DOM 计数烟测（iframe 1→2→1）只能证明路径走通，证明不了效果正确**——本批就是只用计数烟测报了"实证通过"

**v3.1.9 发版处置（用户裁定方案 B，2026-11-25）**：总开关 `TURN_FX_ENABLED=false`（`src/reader/epub/turnFx.ts`）——翻页逻辑逐行回到 v3.1.8（不排队、不建 GhostView、不预热），设置选项恢复「无 / 淡入淡出 / 滑动」，已存的 cover / paper 按渐隐处理。动画阶段修完下面三处根因并**逐帧截图验收**后置 true，再放出新效果。

### V-8 自动整理归类（F-3 决议；规则方案 2026-11-25 依真实书库试算拟定，**待用户确认后开工**）

**设计依据（对本机书库 346 本的只读试算：`node tools/cdp/dryrun-organize.mjs`，只输出计数）**
- 278 本漫画（外部文件夹引用）+ 68 本小说（库内 EPUB，`format` 字段为空——判别介质看 `format === "images"` 取反）；漫画作者字段已有 274 / 278（导入时从文件夹名拆出）→ **归类直接用作者字段，不再解析文件名**
- 用户现有的组织方式：先按介质（漫画 / 小说 / 轻小说），漫画下再按作者建子架（12 个，规模 3–12 本）；漫画根下仍有 185 本未归作者，其中 91 个作者只有 1 本
- 试算命中：作者字段需修正 25 本（空占位 15、作者栏粘了简介 7、国籍前缀 2、站点后缀 1）；同一作者多种写法可归并 21 本；发布标签可提取 已汉化 221 / DL版 100 / 生肉 49 / 无修正 39 / AI生成 4；系列 12 组 31 本；66 本可解析卷号
- **被数据证伪的原设想（不做）**：漫画宣传页按文件名识别 0 命中（抽样 69 本）；轻小说无法从作者 / 书名可靠判断（假名信号仅 1 本，现有「轻小说」架保持手动）；「自动生成作者标签」与作者子架重复、会一次新增约 230 个标签（现共 14 个）→ 取消

**原则**：一键整理 = 预览 → 勾选 → 应用 → 可撤销；每个动作分「高置信（默认勾选）/ 仅提示（默认不勾）」两档；规则内置、无配置项；**只改库内记录，永不动源文件**。

**流水线（全部是纯函数，可单测；输入 = 书籍列表 + 书架树）**
1. **字段清洗**
   - 作者：空占位（空 / 不详 / 未知 / 佚名 / 无名氏 / 其他…）→ 置空并进「待补」清单；`作者,简介` → 拆开，简介补进空的简介字段；去国籍前缀与站点后缀；全半角、空白归一
   - 标题（小说）：书名号包裹 → 去掉；尾注（完结 / 全书完 / 章数范围 / 出品 / 定制…）→ 从标题剥离，章数范围转入备注
2. **身份归并**
   - 作者组：`社团 (作家)` 与单独的社团名、单独的作家名视为同一作者组（并查集；比较时忽略大小写、全半角、空白）；展示名取最完整的写法
   - 系列键：标题 → 去发布标签与括注 → 截断副题 → 去卷号尾 → 归一；系列 = 作者组 + 系列键
   - 卷号：`LEVEL_n` / `第n卷` / `n~m` / `n` / `n.m` / `+n` → 数值，用于组内排序
3. **规则（动作）**
   - **R1 漫画作者归架**〔高置信〕：漫画根下、作者组 ≥ **3** 本 → 新建或归入「漫画 / 作者」子架（阈值 3 = 现有子架的最小规模）；只有 1–2 本的留在漫画根，否则会多出约 90 个单本子架。试算：19 个子架、62 本
   - **R2 状态标签**〔高置信〕：从标题里的方括号标签与 `source_tags` 生成 5 个固定标签：已汉化 / 生肉 / 无修正 / DL版 / AI生成（已有同名标签则复用；用户手动打的标签一律不动）
   - **R3 卷序**〔高置信〕：同系列内按卷号写自定义排序值，没有卷号的排最后
   - **R4 作者修正与归并**〔高置信〕：清洗后的作者写回；归并只统一展示名，原写法存进 `source_tags` 供回溯
   - **R5 重复提示**〔仅提示〕：同系列且标题去卷号后相同 → 列出各份所在书架与位置，转到书库体检处理（不在整理里删除）
   - **R6 缺失作者**〔仅提示〕：能由同系列其他卷推断的给建议，其余列入「待补」
4. **预览弹窗**：按动作分页（归架 / 作者 / 标签 / 卷序 / 提示），每行「原值 → 新值」，顶部汇总；应用前快照受影响字段，支持「撤销上次整理」

**用户确认（2026-11-25）**：① 作者子架阈值 3 ✓ ② 5 个状态标签要做 ✓ ③ 那个书架确是书单，但**转换与去重由用户自己处理——整理功能不做「书架转标签」** ④ 入口两处 ✓

**新增需求（用户同日提出）**：新用户导入新书（小说 / 漫画）时就要**自动识别**（作者、系列、翻译状态等）——体验要直觉、合乎人性，**不要生硬机械的排列，也不要强制归类**。落地口径：导入时用同一套识别引擎给建议，高置信的自动应用、其余不打扰；整理功能面向存量书库；**任何自动动作都不覆盖用户手动改过的作者 / 书架 / 标签**。

**实施注意**：判别介质用 `format === "images"` 取反（小说的 `format` 为空）；试算脚本 `tools/cdp/dryrun-organize.page.js` 里的清洗 / 归并 / 系列键逻辑就是规则引擎的原型，实现时搬到 `src/` 下并补单测。

## 四、基础架构

### V-10 前端热更新 OTA（F-9 决议）——**挪到 3.3**（用户 2026-11-25 裁定：架构大件，不占 3.2）

- **托管**：Cloudflare Pages（国内稳 + 免费 + Git push 自动部署）
- **检测**：启动时（+运行中每 4h）
- **Rust 侧**：`register_uri_scheme_protocol` 自定义协议——优先 serve 本地缓存目录，空/损坏回退内嵌资源
- **刷新**：下载解压到缓存 → `location.reload()` 无感刷新

- **版本锁红线（用户强调）**：
  - 热更新包**严格绑定当前 Rust 后端版本号**
  - 前端 diff 涉及 `#[tauri::command]` 变更 → 热更新通道**自动跳过**，强制提示走整包更新
  - 防新前端调老 exe 里不存在的接口导致白屏崩溃
  - CI 路径过滤自动判定：`src-tauri/**` 有 diff → 走 tag 流程；仅 `src/**` → 走 Pages 部署

### V-11 断点续传（3.1 遗留）——**砍掉**（用户 2026-11-25 裁定：安装包仅约 6MB，自实现续传收益低）

- 更新包 5MB 虽小但仍可能断网——Range 请求续传（updater 插件不支持，需自实现或 patch）


### V-12 更新安装包临时文件自动清理

- `run_update_installer` 启动安装器后延迟 30s 自动删 `%TEMP%ookreading-update\`（安装器已读入内存，删不影响安装）
- **实现口径（2026-11-26 改定，见第十节）**：启动安装器后前端立刻退出应用，进程内的延时清理活不到那时候——改为**启动时清理**该目录（安装器还占着文件就隔 90s 再补一次）
- 热更新通道（V-10）天然无此问题——前端包直接解压到应用缓存，不产生安装包文件


### V-13 漫画/PDF 翻到最后一页提示（2026-11-24 用户提出，杂项）

**现象**：漫画翻到最后一页再翻无反馈，不确定是不是真到底了。
**方案**：到达末页再往后翻时，屏幕正中弹一个**极小的淡入淡出提示**（如「已是最后一页」），1 秒自动消失、不阻挡交互。EPUB 同理（末章再翻显示「已是最后一章」）。样式走碳墨 token（纸底墨字小胶囊，与 toast 同语言但更轻）。
**防骚扰**：连续触发只重置倒计时不叠弹（同一 key 节流 2s）。

## 八、EPUB 处理链 / 展示链审计发现（2026-11-25，翻页动画开工前的只读审计；**已于 2026-11-26 在 3.2.1 批次 B 逐条处置，结论见第九节表格**）

来源：三路只读审计（epub.js 内部机制 / 应用侧阅读展示管线 / Rust 侧 EPUB 处理链）。总体结论：**无高危项**——非测试代码无 panic 路径、无 zip-slip 面、不覆盖用户文件。下列条目除标「已复核」者外引自审计报告的源码行号，动手修之前先自行复核。

### epub.js（0.3.93）与应用侧展示
- **blob URL 永不释放（已复核）**：`Archive.destroy()` 遍历 `urlCache` 的键（压缩包路径）去 revoke，而 blob: 地址在值里——revoke 是空操作；`Resources.destroy()` 只置 undefined。每开一本书泄漏一批图片 / 字体 blob，直到页面卸载
- **rendition 队列会永久停摆（已复核）**：`Rendition._display` 失败只 emit `displayerror`、不 settle 自己的 `displaying`，队列里那个任务永不结束；只有再次 `display()` 能解卡。翻页动画的 `ctrl.turn()` 不走这条队列所以不受影响，目录 / 搜索跳转等走 `display()` 的路径受影响
- **首帧测量早于主题注入**：`IframeView.render()` 内首次 `expand()` 在 `hooks.content` 之前，修正靠 ResizeObserver → rAF 晚 1–2 帧；其间 `next()` 的章内 / 跨章判断读的是无主题布局的 `scrollWidth`（运行时未证实；翻页动画在跨章后同步 settle，截图不受其害）
- `scrollBy` 的 `ignore` 标志按「一次程序化滚动 = 一个 scroll 事件」配对，某次赋值没改变位置则标志残留、吞掉下一次真实 scroll
- `relocated` 给出的 CFI 对中文是**文本节点级**（`splitTextNodeIntoRanges` 按空格切，中文无空格）——进度 / 书签的最细粒度是一个文本节点
- `currentLocation()` 随页码线性变贵（TreeWalker 从 body 开头逐文本节点取矩形），每次 relocated 重算
- `Themes.add` → `addStylesheetRules` 是追加而非替换：反复 `registerThemes()` 时当前主题的规则在表里累积
- 每个 Rendition 往共享的 `spine.hooks.content` 多挂一条 `injectIdentifier`、一条 `unload` 监听，`destroy()` 不注销（现在只有一个 rendition，影响小）。Chromium 158 对这条 `unload` 监听按弃用策略打一条 Permissions policy 日志，无功能影响
- 设置浮窗里的阅读默认只写库，阅读页挂载时才读——已打开的书不随浮窗设置即时变化（现状如此，是否要改待定）
- 漫画 / PDF 的折页覆盖层 `.wr-fold-layer` 底色用 `var(--wr-paper)`，夜间 / 墨夜下该 token 是 6% 白（半透明）——**未实测**，疑似与 EPUB 这边的「根因 B」同病

### Rust 侧 EPUB 文件处理
- **`.opt.epub` 存在但打不开时没有回落原书**：`try/catch` 只包「读文件」，解析失败直接报「EPUB 打开失败」；且 `.opt` 生成后不再重建
- **阅读器打开的是 `.opt.epub` 而不是用户文件**（凡含可测图片的库内 EPUB）：优化会整段删除 `<video>/<audio>`、给 `<img>` 注入 width/height（尺寸表按文件基名建键，不同目录的同名图片互相覆盖）→ `.opt` 与原书分页可能不同，含音视频的书 CFI 不等价；而 locations 缓存键只含书 id + 字体字号
- 删除书籍（详情弹窗）不清理 `.opt.epub`，只有回收站 purge 清；导入中途失败留下的 `.part` 孤儿无人清
- 入库不校验 EPUB（任意改名文件可入库，打开才报错；move 模式此时源已进回收站）；`read_book_file` 的库内分支恒失败（潜伏，目前只有引用书走它）；若干「声明大小」上限可被伪造的 zip 头绕过（内存型风险）；导入同步等待整个重打包
- 图片重编码不保留 EXIF 方向与 ICC；webp 仅无损编码；EPUB 2 封面页指向 XHTML 且候选尺寸解析失败时可能丢封面
- TXT → EPUB：无 BOM 的 UTF-16 不识别；含错字节的 UTF-8 会落到 GB18030；未处理 U+FFFE / U+FFFF
- 依赖版本：zip 2.4.2（另有传递依赖 zip 9.4.1 并存）、rusqlite 0.32.1、image 0.25.10 等——是否带已知漏洞**未证实**

**批次 C：V-3 开场动画（纸墨淡入）**
- 形态：壳第一次挂载时根节点带 `.wr-shell--intro`——侧栏淡入 360ms，主栏晚 80ms 起步再淡入 360ms，**共 440ms**。只改 opacity：不动布局、不挡数据加载；标题栏与窗口钮不参与，全程可点。

- 收场：等主栏那段的 `animationend`（它带延迟、最后结束）才撤类；侧栏先结束就撤的话，主栏会从半透明直接跳到不透明。「减少动态效果」下 CSS 动画被全局回退关掉、不会有 `animationend`，挂载时直接收场。

**已知限制（本版不修，记档）**
