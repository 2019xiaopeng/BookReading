## 一、收藏页同步升级（2026-11-12 用户提出，已设计待实施）

**现状**（FavoritesPage.tsx:135-209 实证）：书籍 tab 是手搓旧卡——非共享 BookCard，无 ⋯ 菜单/右键/拖动/多选/密度/进度墨线/时长 chip，封面 img 无 lazy，两张大文字按钮（打开/已收藏）；是 M2 改版唯一没跟上趟的屏。

**设计原则（ponytail）**：收藏页是"精选视图"不是管理中枢——能继承的全部继承，收藏特有的动作才新增，不做重复的管理设施。

| # | 项 | 方案 |
|---|---|---|
| F-1 | **书籍 tab 换用共享 BookCard**（一步继承全套） | 复用 src/library/BookCard.tsx：⋯ 菜单（同款八项：置顶/详情/重命名/移动书架/备注/封面/收藏/打开位置/从电脑删除）、右键=⋯、拖到侧栏书架=移动归属、密度三档（读全局 library_density）、封面墨线+在读 2px 墨线+已读时长 chip、骨架/lazy/空态。BookCard 增一个可选 prop：`favoriteQuickToggle`（hover 快捷心形钮=快速取消收藏，收藏页传；⋯ 菜单里的收藏项保留双保险） |
| F-2 | 批量模式 | 复选图标钮 + 批量条**只保留三个有意义的动作**：批量取消收藏 / 批量移动到书架 / 全选·取消。不做删除/打标签（收藏页不承担删除场景） |
| F-3 | 排序 | 收藏页内排序下拉：最近阅读 / 书名 / 作者（沿用 LibraryPage 排序菜单组件；**不做自定义拖动排序**——收藏无顺序语义，拖动能力=拖去书架（F-1 已含）） |
| F-4 | 摘录 tab | 右键句子卡 = 菜单（复制文本 / 定位到原文 / 删除）；卡片书名可点跳详情。搜索/按书筛选/导出已有不动 |
| F-5 | 视觉 | 换 BookCard 后自动 M2 化；摘录卡 U5 已 token 化；刊头统计已有（收藏 N · 摘录 N） |

**实施要领**：FavoritesPage 自持一个 MenuState（kind:"book" 同款 + kind:"quote" 新增）与 onCardMenu 回调（LibraryPage 的菜单渲染段可抽共享组件或最小复制——以最小 diff 为准）；不引入新书架拖拽逻辑（drop 目标全局已有）；预计改动集中 FavoritesPage.tsx + BookCard.tsx（一个 prop）。
**验收**：收藏页 ⋯/右键与书架同款且动作全通（含从电脑删除/打开位置）；拖卡到侧栏书架生效；批量取消/移动；摘录右键三动作；密度联动；npm test 全绿。

## 二、ponytail 代码审计发现（2026-11-12，v2.6.0 后全库）

**审计范围**：本仓库是一个 Windows 单用户桌面阅读器（Tauri+React+Rust+SQLite）；假设负载=单用户单进程，**外加一个真实两进程场景：正式版与 dev 版同时开（共享同一 SQLite，WAL 已护库）**。重点通读：epub_optimize.rs 全文、scan_health、tts.ts、HealthScanDialog 删除链、delete_books_from_disk；未逐行读：ReaderPage 全文、weread.css、存储迁移老代码。

### Must fix

1. **`.part` 临时文件并发碰撞**（`src-tauri/src/commands/epub_optimize.rs:179-183`）
   - **是什么**：优化副本写到固定名 `{opt}.part` 再改名上位。
   - **问题**：启动后台补生成线程与"强制重导入同书"的导入内联优化可能同时处理同一本——两个写者互踩同一个 .part，损坏的 zip 被 rename 成正式 .opt，阅读器打开即失败。
   - **修法**：临时名加唯一后缀（`{stem}.opt.{uuid}.part`），rename 前谁先写完谁上位。一行级。
   - **不修的后果**：低概率但属于数据完整性类；出错时用户需手删 .opt 才能恢复阅读。

### Should fix

2. **scan_health 的 basename 重复键是死逻辑**（`src-tauri/src/commands/library.rs:967-974`）
   - **是什么**：复制入库的文件名是 uuid，basename 键永不成组；注释声称"与前端同口径"但前端用的是导入时源文件名。
   - **问题**：不产生错误结果，但误导后来者以为它在工作。**修法：删掉该分支**（title+size 单键已覆盖真实重复），删优于改注释。
3. **大写扩展名口径不一致**（`epub_optimize.rs` 候选用 lowercase 判 `.epub`；`reader.ts` 探测只匹配小写 `/\.epub$/`）
   - **问题**：用户导入 `BOOK.EPUB` → 后台生成了 .opt 却永不被前端使用（白占磁盘）。**修法**：导入时扩展名统一转小写（源头归一）。

### Nice to have

4. **TTS 单段失败即停整队**（`src/reader/tts.ts:94-96`）：`onerror` 置 idle 不续播——一章中某段引擎报错就全停。可改为"错误也前进"并加连续失败熔断；一期可接受。
5. **301MB 级书导入内联优化耗时 200s+**（`import_book` 同步调用 optimize）：导入进度条全程"导入中"易被误认为卡死。可把内联改为"入库即返、首启 backfill 兜底"，或导入提示文案注明"正在优化插图"。

**Verdict:** 健康可发。#1 建议随 v2.7 首批修（一行级），#2/#3 顺手清。
**Lean:** scan_health 死分支 -8 行。
**Not checked:** ReaderPage 3 万行全文、CSS、存储迁移深路径；正式版+dev 双进程下 settings 写穿互相覆盖（用户级风险=设置抖动，非数据丢失，未深查）。
