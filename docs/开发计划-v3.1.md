## 一、需求清单（用户逐条补充）

### U-1 侧栏书架树固定高度 + 内部滚动（2026-11-20 用户报告）

**现象**：书架全部展开后，侧栏顶部「全部藏书/在读/未读」chips 行与底部动作区（刷新/导入/设置）被挤出视口。
**根因**：侧栏为整体 flex 布局，书架树区无独立高度约束（v2.9 S-3 只做了 `overflow-y:auto` 但没做三段布局，AppLayout 重构后未复检）。
**修法**：侧栏改固定三段——顶部品牌+chips 区固定高 / 书架树区 `flex:1; min-height:0; overflow-y:auto` 内滚 / 底部动作区固定高。全展开任何数量书架，头尾永不被挤走。
**验收**：全展开 50+ 书架，chips 与底部四钮始终可见，树区内部滚动流畅。

### U-2 鼠标侧键在最深子目录：松手弹回（2026-11-20 用户报告）

**现象**：在最里层子书架按住回退侧键 → 回到上级；**一松手又跳回当前最深层子目录**。
**根因假设**（v2.9 M-3 遗留）：mousedown 捕获期 preventDefault 只吃掉了按下相的默认 history.back，我们同时做了逻辑导航（push 入历史栈：…child → parent）；**松手相（mouseup/keyup）WebView2 仍执行默认回退** → history.back() 把栈退回 child。修法：button 3/4 的 **mouseup 相也捕获 preventDefault**；或逻辑导航统一用 `replace` 不 push，使默认回退无路可退；真鼠标实测三种场景（深层/根/收藏回收站）。
**验收**：最深层按一下（非按住）回退=到上级且松手不弹回；连按两下=再上一级。

### U-3 阅读页返回书库：密度先小后大闪一帧（2026-11-20 用户报告）

**现象**：从漫画/小说阅读页退出到书库，书卡网格先以最小密度渲染，一瞬后才切到用户设定的中/大密度。
**根因假设**：密度设置（library_density）异步 getSettings 加载，首帧用默认档渲染、设置到达后二次渲染。修法：设置在应用启动时一次性预热进模块级缓存（batch7 已有 libraryBooksCache 先例），密度/排序等首帧即同步取缓存值；或网格容器在设置就绪前不渲染（骨架占位）。
**验收**：来回进出阅读页 10 次，网格密度零跳变；书多（200+本）时同样不闪。

### U-4 标题清洗 v2：更精准（2026-11-20 用户报告）

**现状**：v2.9 N-1 八步管线（实体解码/双语拆分/发布标签/水印前缀/出处后缀/空白/作者/兜底）+ 预览 diff 一键应用；实际用下来仍不够精准——**汉化组名误识别或漏识别**、残留杂符号/空格。
**方向**（开工时定案）：
1. **全库标题抽样统计**（用户建议拉更多样本）：把书库全部标题跑一遍现行管线，聚类"未命中的残留段"和"误命中段"，据实扩词表/改规则——不拍脑袋加规则
2. 汉化组识别从"词表命中"升级为**模式识别**：`[纯中文 2-8 字短词组]` 前缀、含"汉化/翻訳/字幕/組/组/production"等后缀特征的括号段，词表做加分项而非唯一判据（降低对未知组名的漏识）
3. 误识别防护：清洗预览已有 diff 机制——加"回退单本"能力，误洗可一键还原
4. wenku8 拉取的标题走同一管线（v3.0.1 已接），规则改进两处同享
**验收**：抽样 100 本人工核对，残留/误判率显著下降；未知汉化组名（词表外）能被模式规则命中；误洗可还原。

### U-5 阅读器目录分层渲染（2026-11-20 用户报告，已实锤根因）

**现象**：Z-Library 下载的书（实测《母上攻略》，`library/books/2303bdb4-….epub`）在站上目录有卷有章，本应用打开只剩一列平铺——"太简陋、偏差很大"。
**根因（已解剖样本）**：该书 toc.ncx `dtb:depth=2`，navPoint「第一卷」嵌套子 navPoint「第一章 …」——层级数据完整；**阅读器 TOC 面板把 epub.js 的嵌套 toc 平铺渲染**（src/reader/epub/ TocItem/tocLabelFor 一带）。
**修法**：TOC 面板按 toc 嵌套深度渲染树（卷=可折叠分组、章=叶子，缩进/图标分层；当前章高亮逻辑沿用）；扁平目录书（depth=1）自然退化为现状不分层。
**验收**：《母上攻略》目录显示"第一卷 > 第一章 …"层级；《我内心的糟糕念头》（wenku8 txt 转制，平铺）不受影响；350 章长书滚动定位仍正常。

### U-6 自制书向导（2026-11-21 用户确认入档）

**分期**：
- **U-6a 轻量向导**：选多个 TXT / 设分章规则 / 选封面 / 填元数据 → 生成 EPUB 直接入库（复用现有 txt_to_epub + 导入管线，工程量小）
- **U-6b 插图 + 目录编排**：图片插入指定章节、手动调卷/章——**等 U-5 目录树落地后评估**（视图与编辑共用同一棵树）
**不做**：完整 EPUB 编辑器（=重造 Sigil）。兜底：外部 Sigil 编辑后重新导入（链路今天已通）。

### U-7 过场动画组（2026-11-21 用户提出，设计届时讨论）

- **U-7a 开书加载过场**：大书加载时现状"把显示页面挤到一侧"（加载态布局推移，观感差）——做专门加载过场动画；顺带修加载态布局不挤占阅读区的问题
- **U-7b 应用开场动画**（splash / 开场过场）

**技术选型备注**（讨论结论）：CSS transition/animation + FLIP 优先（覆盖 90% 界面动效，零依赖）；弹性物理动画（Flutter 感）= **framer-motion**（React 标配，约 50KB）；**不上 three.js/WebGL**——包体积与 WebView 性能代价大，仅当真要 3D 翻书卷曲/粒子开场才值得，当前需求不需要。

### U-8 正文显示区域自适应（2026-11-21 用户提出）

**现象**：文字显示区占屏比例偏小；小屏幕上更明显。**方向**：正文区宽度/页边距按窗口尺寸自适应（小窗→边距占比收窄、正文区占比放大；大屏维持现有留白）。现有手动页边距设置（v2.6 排版细项）保留，自适应只改默认档。**验收**：1366 笔记本屏与 4K 桌面屏都无"字悬在一小条"感。

### U-9 启动闪白（2026-11-22 用户提出）

**现象**：应用启动瞬间白屏闪一下再进入主题界面。
**根因方向**：WebView2 默认白底 + 前端主题 CSS 加载时序。修法：窗口创建即设主题色背景（tauri window backgroundColor 跟随上次主题）+ 入口内联首屏底色；与 U-7b 开场动画联动设计。

### U-12 代理设置（保障更新稳定下载）（2026-11-22 用户提出）

**背景**：用户实测应用内更新下载常因网络波动失败（v2.7 只有"直连失败自动试本地代理"的硬编码探测）。
**方向**：设置里可配代理（host:port，HTTP 代理起步），应用于更新检查/下载与云书架请求（reqwest 原生支持）；策略=直连优先、失败自动走配置代理；下载支持断点续传减少重下。

现浮窗（SettingsDialog）→ 独立路由页面（如 /settings）：左侧分区导航（外观/阅读/书库/云书架/网络与更新/快捷键/关于…）+ 右侧大内容区。审美沿用书库设计语言基准；与 U-7 动画组、U-12 代理项同期设计（U-12/U-11 的设置入口自然落在此页）。

### U-14 全局自绘右键菜单，替换 Chromium 原生菜单（2026-11-22 用户提出）

**现状**：仅书卡/漫画有自绘右键（v2.6 ⋯ 菜单同款），其余区域右键弹 Chromium 原生菜单（刷新/另存为…浏览器味）。
**方案**：全局 `contextmenu` preventDefault；按区域注册菜单（侧栏书架树=新建/重命名/删除书架、书卡=沿用现有⋯、阅读正文=复制/查词预留/高亮、输入框=剪切复制粘贴（原生行为保留或自绘）、云书架卡=详情/拉取/网页版、回收站=恢复/彻底删…）。实现路径二选一：前端 contextmenu 事件 + wr-menu 复用（现有体系）；或 WebView2 层关默认菜单（AreDefaultContextMenusEnabled）+ 全前端接管。
**补充（2026-11-22）**：不需要菜单的区域直接屏蔽右键（preventDefault 后不出任何菜单），不是到处都塞菜单。
**验收**：全应用任何位置右键只见自家菜单或无菜单，无一处原生菜单。

### U-15 浏览器痕迹清理（选中色/拖拽预览/快捷键审计）（2026-11-22 用户提出）

- **选中高亮**：::selection 全主题跟随（阅读正文与界面两处，八套主题各自定义，替换 Chromium 默认蓝）
- **图片拖拽预览**：全局 img/user-select 拖拽治理（draggable=false 或 dragstart preventDefault），书卡拖拽归架等自家拖拽不受影响
- **快捷键审计**：Ctrl+F/Ctrl+P/Ctrl+S/F5/Alt+左等浏览器默认行为逐一排查——确保只触发应用自己的（Ctrl+F 已有应用内搜索；其余默认应吞掉）；输入框内的编辑快捷键保留原生
**实现提示（正式）**：WebView2 层总开关一条龙——`AreDefaultContextMenusEnabled=false`（配 U-14）、`AreBrowserAcceleratorKeysEnabled=false`（一键禁全部浏览器加速键，比前端逐个拦干净）、`IsZoomControlEnabled=false`（禁 Ctrl+滚轮整页缩放，我们阅读器自己管缩放）；输入框编辑键不受影响需实测确认。前端层仅做补充（::selection/dragstart/应用内快捷键）。
**验收**：选中文字颜色随主题；拖图无浏览器拖影；Ctrl+F/P/S/F5 无任何浏览器行为。

### U-16 阅读页顶栏窄窗挤压（2026-11-22 用户报告）

**现象**：读书时缩小窗口，顶栏按钮（返回书库/设置/目录…）全部挤在一起。
**方向（2026-11-22 用户澄清：不预设"低频钮收起"方案）**：候选含溢出折叠/分组收纳/双行工具栏/侧栏化等，届时讨论更好的方案；硬指标只有两条——全功能可达 + 不挤压。书库页三档断点（720px 起）已有先例，阅读页顶栏缺同等处理。
**验收**：任一窗口宽度下顶栏不挤压不换行错乱，全部功能可达（可能收进⋯）。

## 二、3.2+ 展望（暂存，3.1 之后讨论）

### F-1 UI 组件层系统升级（2026-11-22 用户提出，方向已定：不换脚手架）

**用户诉求**：手搓 UI"用是可以用，就是不够好"——问是否换组件库/脚手架。
**裁定（讨论结论）**：不整库替换（shadcn/AntD/MUI = 测试全洗牌 + 碳墨语言推倒重来，痛点也不由此解决）；做**组件层系统升级**：
1. 引入 **Radix UI 类 headless 无样式基座**垫在碳墨 token 皮肤下——菜单/对话框/下拉的键盘导航、焦点管理、无障碍、展开收起行为由基座承担，视觉仍自有
2. 抽出自有原语层（Button/Menu/Dialog/Input/Toolbar 内建响应式溢出规则，U-16 的解法沉淀于此）
3. 全页面**窄窗响应式审计**（每页 3~4 档宽度走查，列入验收清单）
**验收**：组件行为达到库级手感（键盘/焦点/响应式），视觉仍是碳墨，测试不回退。
