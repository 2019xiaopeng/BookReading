趁现在额度用完正好停下来复盘——刚才 Claude Code 之所以反复翻车，本质上不是它写代码粗心，而是它一直在 **`epub.js` 这个十年前的老旧单视口框架外面硬套补丁**。

我帮你调研了目前主流开源阅读器（如同样基于 Tauri 构建的 **Readest**、Linux 旗舰阅读器 **Foliate**、行业标准 **Readium** 以及仿真库 **StPageFlip**）的真实底层架构，把行业里真正成熟的两大类翻页实现方案拆解给你看：

### 一、 先看清病根：为什么 `epub.js` 这么难做推拉滑动？

`epub.js` 内部只有一个 `iframe` 视口，翻页时它直接把里面的内容瞬间跳切（或销毁重建）。**同一瞬间，屏幕上永远只有“一页”存在**——没有“旧页”和“新页”同时同框，自然没法做出“旧页向左推出、新页从右侧推入”的物理衔接。Claude Code 之前试图用 JS 去克隆 `iframe` 里的网页节点，又被 `epub.js` 动态生成的 `blob:` 样式表拦住，最后只能退化成“原地微移 24px”。

### 二、 主流阅读器怎么做「无缝整页推拉滑动」？

行业里有两条完全成熟的路线，一条是**彻底换引擎的架构级方案**，一条是**不换 `epub.js` 的浏览器底层黑科技**：

#### 路线 A：CSS 多栏长卷轴 + 原生平滑滚动（`foliate-js` / `Readest` 方案）

目前 GitHub 上最火的新一代开源阅读器 **Foliate** 和 **Readest**（技术栈也是 Tauri + React）全部弃用了 `epub.js`，转而使用 **`foliate-js`**。

- **章节内翻页原理**：它不把一章切成孤立的单页，而是用 CSS Multi-Column（`column-width: 100vw`）把整章排版成一条**横向无限延伸的多栏长画卷**，第 1 页、第 2 页、第 3 页在 DOM 里本来就是左右紧挨着排好的。翻页时，程序只需调用浏览器底层的横向平滑滚动（`scrollTo({ left: 下一页坐标, behavior: 'smooth' })`）——因为两页本来就挨在一起，推拉滑动是 100% 物理真实的，绝对不可能出现空白页。
- **跨章节边界怎么防闪白**：当读完第一章要切进第二章（必须加载新 HTML 文件）时，**Readest** 和 **Readium** 的做法都是在切换瞬间截取一帧旧画面的像素快照盖在顶层，等新章节在底层加载排版完毕后，再让旧快照向左滑出、新章节从右滑入。

#### 路线 B：WebView2 原生 `View Transitions API`（不换 `epub.js` 的最优解）

如果你不想在短期内把 `epub.js` 整套替换掉，Tauri 2 在 Windows 上调用的是系统内置的 Edge WebView2（Chromium 内核），它原生支持一项现代浏览器特性——**`document.startViewTransition()`**（Readest 在桌面端也用到了这项技术）。

- **为什么它能绕开 Claude Code 遇到的所有坑**：之前 Claude Code 报错是因为它用 JS 去复制 HTML 节点，复制不了 `iframe` 里的样式；而 `startViewTransition` 是**显卡合成器（GPU Compositor）级别**的机制——它在翻页前直接对整个屏幕（包含 `iframe` 内部画面）拍一张显存级位图快照，等底层 `epub.js` 翻到下一页并渲染完成后，浏览器会自动把“旧画面位图”和“新画面位图”交给显卡做并行动画（比如旧图 `translateX(-100%)` 滑出，新图 `translateX(100%) -> 0` 滑入）。
- **优势**：代码量极少（几十行 JS + CSS），不破坏 `epub.js` 现有的划线、目录、进度逻辑，且 60/120fps 满帧运行，零空白闪屏。

### 三、 主流阅读器怎么做「真实纸张卷页（仿真翻页）」？

真正的仿真翻页（带圆柱形纸张弯曲弧度、纸背透字、动态高光和投影），绝对不是用 CSS `rotateY` 翻转方框能做出来的，行业里只有两种做法：

#### 方案 1：引入现成的 `StPageFlip`（`page-flip`）库

这是目前 Web 端最主流的开源仿真翻页库，支持“软纸张弯曲”和“硬壳书翻动”两种物理手感，自带阴影和拖拽卷角。

- **适用与局限**：它要求所有页面在初始化时就是固定尺寸的独立区块（`<div class="page">` 或 `<canvas>`）。**非常适合你的漫画阅读器**（漫画本身就是一张张固定图片），但**很难直接塞进动态排版的 EPUB 小说里**（因为小说一调字号或拉动窗口，总页数就会实时重算）。

#### 方案 2：离屏快照 + 2D Canvas / WebGL 卷页着色器（Apple Books / Readest 方案）

这是目前高端阅读器实现“动态排版小说也能仿真翻页”的标准架构：

1. **平时阅读时**：画面就是纯粹的网页文字，保证你依然可以正常鼠标划词选中、高亮、做笔记。
2. **触发翻页的 300ms 内**：程序在后台把当前页和下一页各自渲染成两张高清内存贴图，在最上层临时盖一层透明的 `<canvas>`，用数学公式/着色器实时绘制纸张弯曲、背面半透明反光和折痕阴影动画。
3. **动画结束瞬间**：立刻销毁这层 `<canvas>`，把底下真正的文字层露出来。

### 四、 给 BookReading 的落地路线建议

结合你追求**轻量、低延迟、拒绝臃肿依赖**的原则，等下个月额度恢复后，建议按这个性价比顺序来推进：

| **1. `View Transitions API` 推拉滑动** | 真正的整页左右推拉衔接，零空白页  | **极低**（不换引擎，仅改动翻页过渡层）     | **v3.2 首选**：用最小改动把 EPUB 平移翻页做到位              |
