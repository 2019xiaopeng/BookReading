**诉求**：书架越来越多，侧栏树会超出可视高度——需要折叠/展开。

**设计**：

| # | 项 | 方案 |
|---|---|---|
| S-1 | 折叠交互 | 有子书架的树节点（wr-nav-group-btn）行尾加 ▸/▾ 旋转小箭头（或点行名=进入、点箭头=折叠，两区分离防误触）；折叠状态存模块级 Map（会话内）+ settings 键 `shelf_collapsed`（跨会话，JSON 数组存折叠的 shelf id） |
| S-2 | 全部收起/展开 | 侧栏树顶部（快捷 chips 下方或树标题行）加「全部收起 / 全部展开」文字小钮 |
| S-3 | 长树滚动 | .wr-nav-groups 超高时 overflow-y:auto（现无上限，靠壳层滚动——核对两处滚动嵌套的手感，取自然的一层） |
| S-4 | 计数联动 | 折叠的架：递归计数仍上卷到父行显示（K-4 的 rollupShelfCounts 已支持，纯展示问题） |

**验收**：折叠后子架隐藏且计数并入父行；重启保持折叠态；全部收起→树只有根级；箭头点击不触发进入书架。

## 二、v3.0 预研：wenku8 在线书架（2026-11-19 用户提出，本期只探讨不实施）

用户已在手机实测 Wenku8_Flutter：登录轻小说文库账号后云端书架原封同步。完整流程已调研清楚（源码：Wenku8_Flutter 公开快照 + [pywenku8api](https://github.com/WorldObservationLog/pywenku8api) 全量实现）：

### 两条接入路线（wenku8 无官方开放 API，全是社区逆向）

| 路线 | 协议 | 优劣 |
|---|---|---|
| **A. 网页版** www.wenku8.net | 传统 PHP 站：GET `login.php?do=submit` 建会话 → POST `action=login&username&password&usecookie`（表单编码）→ 服务端 Set-Cookie 下发 `jieqiuserinfo`（**成功判定=出现此 cookie**，只有 PHPSESSID=失败）。书架=GET `bookcase.php?classid={bid}` 解析 HTML；加/删书架=GET `addbookcase.php?bid=` / `bookcase.php?delid=`；详情/目录/正文=`articleinfo.php?id=` / `reader.php?aid=&cid=`（**GBK 编码**）；搜索=`search.php?searchkey=`（GBK URL 编码，带 charset 参数会被 CF 拦） | 协议简单公开；但**深层模块页有 Cloudflare Managed Challenge**（pywenku8 实测），可能需要浏览器通道兜底；GBK 处理繁琐 |
| **B. App 中继** wenku8-relay.mewx.org（MewX 官方合作 App 同款协议，**Wenku8_Flutter 用的就是这类**） | 单一 POST 端点：body 裸拼 `&appver=<ver>-<magic>-<hmac8>&request=<base64(action=…&do=…)>&timetoken=<ms>`；登录=`action=login&username=&password=`（@ 邮箱用 `loginemail`），返回纯数字（1=成功），PHPSESSID 走 cookie；书架=`action=bookcase`（XML）/`action=bookcase&do=list`（轻量 aid 列表）；正文/目录/搜索/封面/整本下载全是同一端点的 action 变体 | 响应干净（XML/JSON）、无 CF；但 **appver 参数是每 60 秒动态计算的 HMAC-SHA256+magic（逆向官方 App native 层所得）**——pywenku8 公开版刻意不内置此算法（防滥用），需自行实现注入 |
| C. CDN | img.wenku8.com 封面/插图、dlN.wenku8.com 整本 TXT | 伴随资源，非独立路线 |

### Wenku8_Flutter 的书架同步机制（源码实证，可整套借鉴）
- `WenkuShelfSync`：**双向成员同步**（CloudShelfPlan 纯函数算三向合并：本地新增→上传、云端新增→下载、双方删除→互删），2 分钟轮询+前台触发；**只同步书架成员关系，不上传本地进度/文件**
- 进度/标注：走它自己的 `.wenku8sync` 文件手动合并（S3/WebDAV），与 wenku8 账号无关——**wenku8 服务端不存阅读进度**，各客户端自管
- 云端书 → 本地：`mergeCloudToLocal` 把云书架 aid 列表落成本地书条目，正文按需抓取+离线缓存（offline_cache.dart）

### 对 BookReading v3.0 的可行性判断
- ✅ 完全可行，建议**路线 A（网页版）为主**：无需逆向 appver 算法，法律灰色更浅；CF 挑战用"登录页+浅层页直连、深层页带浏览器 UA/重试"策略，实在不行提示用户
- 落法：设置新增「在线书源」区（wenku8 登录表单）；登录后侧栏出现「云端书架」分区（与本地书架并列展示，标记☁徽标）；点云端书=按需抓取正文生成 EPUB 入临时阅读（不占本地库，可选"收藏到本地"一键转正）；同步只做单向拉取（云→本地展示），不做回写（规避滥用）
- 工程量：中——Rust 侧一个 wenku8 模块（登录/书架/目录/正文四个请求+GBK 解码+HTML 解析），前端一个云书架分区+阅读接入；约 2-3 个批次
- ⚠️ 合规注意：wenku8 内容有版权，个人登录+个人书架拉取=与手机 App 同等使用强度；**不提供站内浏览/搜索下载全站**能力，只做"我的书架"投射，控制请求频率
