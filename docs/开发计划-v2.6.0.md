## 一·八、插图多的 EPUB 打开卡顿（2026-11-10 调研结论，未动代码）

**根因链**（reader.ts:275-276 实证）：整本 EPUB 读进 ArrayBuffer → epubjs/JSZip 全量解压驻留内存 → 章节渲染时插图**原图直出**（与漫画缩略档修复前的同款问题：3000px 插图全幅解码塞 760px 纸面）→ 另 v2.5.0 的 locations 后台生成会逐章 load，触发**每张插图的资源膨胀**——插图多的书开书后那阵卡正是它（持久化后只首次痛，但首次很痛）。

| 方案 | 内容 | 收益/成本 | 结论 |
|---|---|---|---|
| **A 导入时"阅读优化副本"**（推荐） | Rust 解包 epub：宽/高 >1800px 或 >1.5MB 的插图 LANCZOS3 缩到 1520px 宽（纸面 2x DPR 上限）；照片型 PNG→JPEG q85、透明 PNG→无损 webp；重打包为 `library/books/{id}.opt.epub`（原书保留，阅读器优先开 .opt）；存量书启动后台幂等补生成（复用缩略档 backfill 模式） | 内存/解码/IPC 全线 5–20 倍降；locations 生成不再被插图拖垮；CFI 不受影响（只换 media 资源不动 xhtml 结构）；一次性成本，运行时零新增复杂度 | **首选**，与漫画降采样同思路同依赖（image crate 已在） |
| B 布局稳定小补丁 | A 顺手做：优化时已知图片尺寸 → 往 xhtml 的 img 写 width/height（分页测量稳定，翻到图页不跳版）；另 content hook 给 img 注入 `loading=lazy decoding=async`（滚到才解码） | B2 是一行级改动，可独立先做 | 叠加 |
| C 运行时钩子缩放 | hooks.content 里 createImageBitmap 逐图缩放换 src | WebView JS 解码照吃 CPU、每章都要跑、复杂度高 | 不先做 |
| D locations 剥离图片跑 | 二次解包出无图 xhtml | A 落地后无必要 | 弃 |

## 二、从 Wenku8 抄的作业（按性价比排序）

| # | 需求 | 落法 | 预估成本 | 验收 |
|---|---|---|---|---|
| 1 | **mobi/azw3 支持**（解锁 P2 最大项） | Rust FFI 挂 libmobi（LGPL，动态链接保隔离）：解包未加密 MOBI→OEBPS→重建 EPUB→走现有导入管线；DRM 一律拒绝并明示 | 中-高（新原生依赖+打包处理） | 导入无 DRM 的 mobi/azw3 正常阅读；DRM 书给出明确错误；license 合规（动态链+声明） |
| 2 | **EPUB 排版细项** | 字重/字间距/四边页边距/段距/首行缩进/两端对齐——全部是 iframe CSS 变量，扩展现有 registerThemes 注入 + SettingsPanel 控件 | 低-中 | 设置面板新控件逐项即时生效并持久化 |
| 3 | **排版设置"按本书"范围** | 把漫画 imgset:<bookId> 覆盖键机制推广为通用 epuset:<bookId>（EPUB 排版项可选"仅本书"） | 低 | 书内改字号/排版只影响当前书，全局默认不動 |
| 4 | **StarDict 离线词典** | Rust 解析 .ifo/.idx/.dict(.dz)（stardict-rs 或自写），划选气泡加"查词"钮→抽屉展示释义；词典文件放 library/dicts/ | 中 | 划选查词秒出；无词典时按钮隐藏 |
| 5 | **TTS 朗读（听书）** | 第一期用 Windows 自带 WinRT 系统合成（免费离线、零依赖）：朗读当前章+跟随高亮+倍速+停止；后期可评估 Edge read-aloud 在线音色 | 中 | 按钮开始/暂停；朗读位置跟随滚动；倍速生效 |
| 6 | 阅读报告图片导出 | Canvas 合成年度/书目报告 PNG（时长/书目/热力格子），走现有 reading_sessions 数据 | 中（偏玩具） | 导出 PNG 落盘并可分享 |
| 7 | 背景图增强 | 浓度调节滑杆 + 多张轮换（单槽→多槽列表） | 低 | 浓度实时预览；多图随机/固定切换 |

不建议项（默认不做，除非拍板）：云同步（与纯本地定位冲突；若做必须 WebDAV+端到端加密）、竖排（epubjs iframe 能力有限）、纸页 shader 翻页。
