## 功能项（原 3.2 计划第二、三节）

### V-5 自制书向导（F-5 决议）

- **单页表单 + 左右分栏**（不做逐步向导——桌面工具不需要"下一步→下一步"）
- 左栏：书名/作者输入、封面选择、分章规则（内置 3 套常用正则预设 + 自定义正则输入）
- 右栏：**实时章节目录树预览**（识别出的卷/章所见即所得）
- 一键生成 EPUB 直接入库（复用 txt_to_epub + import_book 管线）
- **插图编排留 3.3**

### V-6 wenku8 增量更新替换（自旧候选池拉入）

**现状**：连载书显示"有新章"徽标，但要重拉整本太浪费。
**修法**：只拉取新增章节 → 追加进本地 EPUB（zip 尾部插入新 XHTML + 更新 OPF/spine/NCX）→ 阅读进度按章节索引迁移（CFI 前缀匹配，新增章不影响已有进度）。
**验收**：有新章的书点"更新"→ 只下载新增章节（进度条显示 N/M 章）→ 完成后直接继续阅读，进度不丢。

### V-7 wenku8 云端全站搜索（自旧候选池拉入）

**现状**：只能拉取已收藏的书架。
**新增**：接入 `action=search` 全站检索——在云书架页直接搜书名/作者 → 结果列表（封面+元信息）→ 点详情 → 拉取入库。
**入口**：云书架搜索框语义升级（本地过滤 ↔ 云端搜索双模式切换，或搜索结果合并展示）。

### V-8 自动整理归类（F-3 决议；规则方案 2026-11-25 依真实书库试算拟定，**待用户确认后开工**）

**设计依据（对本机书库 346 本的只读试算：`node tools/cdp/dryrun-organize.mjs`，只输出计数）**
- 278 本漫画（外部文件夹引用）+ 68 本小说（库内 EPUB，`format` 字段为空——判别介质看 `format === "images"` 取反）；漫画作者字段已有 274 / 278（导入时从文件夹名拆出）→ **归类直接用作者字段，不再解析文件名**
- 用户现有的组织方式：先按介质（漫画 / 小说 / 轻小说），漫画下再按作者建子架（12 个，规模 3–12 本）；漫画根下仍有 185 本未归作者，其中 91 个作者只有 1 本
- 试算命中：作者字段需修正 25 本（空占位 15、作者栏粘了简介 7、国籍前缀 2、站点后缀 1）；同一作者多种写法可归并 21 本；发布标签可提取 已汉化 221 / DL版 100 / 生肉 49 / 无修正 39 / AI生成 4；系列 12 组 31 本；66 本可解析卷号
- **被数据证伪的原设想（不做）**：漫画宣传页按文件名识别 0 命中（抽样 69 本）；轻小说无法从作者 / 书名可靠判断（假名信号仅 1 本，现有「轻小说」架保持手动）；「自动生成作者标签」与作者子架重复、会一次新增约 230 个标签（现共 14 个）→ 取消

**原则**：一键整理 = 预览 → 勾选 → 应用 → 可撤销；每个动作分「高置信（默认勾选）/ 仅提示（默认不勾）」两档；规则内置、无配置项；**只改库内记录，永不动源文件**。

**流水线（全部是纯函数，可单测；输入 = 书籍列表 + 书架树）**
1. **字段清洗**
   - 作者：空占位（空 / 不详 / 未知 / 佚名 / 无名氏 / 其他…）→ 置空并进「待补」清单；`作者,简介` → 拆开，简介补进空的简介字段；去国籍前缀与站点后缀；全半角、空白归一
   - 标题（小说）：书名号包裹 → 去掉；尾注（完结 / 全书完 / 章数范围 / 出品 / 定制…）→ 从标题剥离，章数范围转入备注
2. **身份归并**
   - 作者组：`社团 (作家)` 与单独的社团名、单独的作家名视为同一作者组（并查集；比较时忽略大小写、全半角、空白）；展示名取最完整的写法
   - 系列键：标题 → 去发布标签与括注 → 截断副题 → 去卷号尾 → 归一；系列 = 作者组 + 系列键
   - 卷号：`LEVEL_n` / `第n卷` / `n~m` / `n` / `n.m` / `+n` → 数值，用于组内排序
3. **规则（动作）**
   - **R1 漫画作者归架**〔高置信〕：漫画根下、作者组 ≥ **3** 本 → 新建或归入「漫画 / 作者」子架（阈值 3 = 现有子架的最小规模）；只有 1–2 本的留在漫画根，否则会多出约 90 个单本子架。试算：19 个子架、62 本
   - **R2 状态标签**〔高置信〕：从标题里的方括号标签与 `source_tags` 生成 5 个固定标签：已汉化 / 生肉 / 无修正 / DL版 / AI生成（已有同名标签则复用；用户手动打的标签一律不动）
   - **R3 卷序**〔高置信〕：同系列内按卷号写自定义排序值，没有卷号的排最后
   - **R4 作者修正与归并**〔高置信〕：清洗后的作者写回；归并只统一展示名，原写法存进 `source_tags` 供回溯
   - **R5 重复提示**〔仅提示〕：同系列且标题去卷号后相同 → 列出各份所在书架与位置，转到书库体检处理（不在整理里删除）
   - **R6 缺失作者**〔仅提示〕：能由同系列其他卷推断的给建议，其余列入「待补」
4. **预览弹窗**：按动作分页（归架 / 作者 / 标签 / 卷序 / 提示），每行「原值 → 新值」，顶部汇总；应用前快照受影响字段，支持「撤销上次整理」

**用户确认（2026-11-25）**：① 作者子架阈值 3 ✓ ② 5 个状态标签要做 ✓ ③ 那个书架确是书单，但**转换与去重由用户自己处理——整理功能不做「书架转标签」** ④ 入口两处 ✓

**新增需求（用户同日提出）**：新用户导入新书（小说 / 漫画）时就要**自动识别**（作者、系列、翻译状态等）——体验要直觉、合乎人性，**不要生硬机械的排列，也不要强制归类**。落地口径：导入时用同一套识别引擎给建议，高置信的自动应用、其余不打扰；整理功能面向存量书库；**任何自动动作都不覆盖用户手动改过的作者 / 书架 / 标签**。

**实施注意**：判别介质用 `format === "images"` 取反（小说的 `format` 为空）；试算脚本 `tools/cdp/dryrun-organize.page.js` 里的清洗 / 归并 / 系列键逻辑就是规则引擎的原型，实现时搬到 `src/` 下并补单测。

## 基础架构（原 3.2 计划第四节）

### V-10 前端热更新 OTA（F-9 决议）——**挪到 3.3**（用户 2026-11-25 裁定：架构大件，不占 3.2）

- **托管**：Cloudflare Pages（国内稳 + 免费 + Git push 自动部署）
- **检测**：启动时（+运行中每 4h）
- **Rust 侧**：`register_uri_scheme_protocol` 自定义协议——优先 serve 本地缓存目录，空/损坏回退内嵌资源
- **刷新**：下载解压到缓存 → `location.reload()` 无感刷新

- **版本锁红线（用户强调）**：
  - 热更新包**严格绑定当前 Rust 后端版本号**
  - 前端 diff 涉及 `#[tauri::command]` 变更 → 热更新通道**自动跳过**，强制提示走整包更新
  - 防新前端调老 exe 里不存在的接口导致白屏崩溃
  - CI 路径过滤自动判定：`src-tauri/**` 有 diff → 走 tag 流程；仅 `src/**` → 走 Pages 部署
