## 已确认（昨晚新发现，此前未落盘）

1. **MewX 官方 Android 开源仓库没有 appver 算法**
   - `MewX/light-novel-library_Wenku8_Android` 的公开版是空桩：api-stub 模块 `Wenku8API.java` 里 `AppVer = "Unknown"`，`LightNetwork` 在 stub 构建上拒绝一切请求。
   - 真实实现在 APK 的 native 层（.so），不在仓库。Release v2.0.0 只有 `.aab`（Play 包），无直接 APK。
2. **wenku8-relay.mewx.org 的本质**：Cloudflare Worker，纯代理官方 `app.wenku8.com/android.php`。appver 签名是**上游官方 API 要求的**，不是中继自己的鉴权。
3. **Greasyfork 脚本 539514「轻小说文库」的完整请求构造代码已拿到**（浏览器脚本必然带可用实现）：


## 关键张力（开工第一件事：实测裁定）

- 裁定文档记述：appver = HMAC-SHA256 + magic，60s 窗口（来自 pywenku8api 的 `appver.py` 契约，`AppverProvider.compute(version, at)`，公开版刻意缺算法本体）。
- 但 greasyfork 脚本实际用：`appver=1.13` 明文常量 + `btoa(request)` + 毫秒 timetoken —— **没有 HMAC**。
- 两种可能：① relay 对旧版 appver 接受简单形式（HMAC 是新版 App 才有）；② 脚本走的是兼容路径。
- **开工第一步**：用 greasyfork 形式向 relay 发一个真实请求（如 bookshelf），通了就省掉整个逆向，appver 模块缩成几行；不通再上 HMAC 逆向路线。
