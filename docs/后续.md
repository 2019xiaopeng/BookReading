结合你目前的藏书结构（361 本藏书里漫画占了近 300 本，外加轻小说、网文和私密分类）以及你的使用习惯（喜欢多开切换看漫画、偏爱「碳墨/纸墨」的印刷质感），你现在的软件功能已经非常全了，下一步产品升级的核心不应该是“继续堆功能”，而是**围绕“重度漫画 + 轻小说阅读器”的真实场景，把质感、连贯性和私密性做深**。   

我从产品和交互设计的角度，为你梳理了四个最具差异化的升级方向：

### 一、 漫画重度体验：从“看单本图片”升级为“系列追漫工作台”

你书库里 80% 以上都是漫画（包含不少生肉日漫），目前软件对漫画的处理还偏向“文件夹看图器”，有三个非常值得做的交互升级：   

- **「系列卷叠放」与「无缝连读下一卷」**
  - **现状痛点**：长篇漫画往往有十几卷，平铺在书架上占地方，看完第 1 卷还得退回书架手动找第 2 卷。
  - **设计方案**：同系列漫画支持自动或手动折叠成“叠放书卡”**（封面右上角显示 `共 12 卷` 叠层边缘，点击展开抽屉选卷）；更关键的是，当翻到第 1 卷最后一页再往后翻时，底部浮出半透明提示条：**“本卷已读完，继续按 → 进入《第 2 卷》”，实现零中断连读。
- **日漫生肉「局部放大镜（Loupe）」**
  - **设计方案**：看日漫时经常遇到小字注音（假名）或背景吐槽文字看不清，如果每次都用 `Ctrl+滚轮` 放大整页再拖来拖去非常累。可以设计成**按住鼠标中键或特定快捷键（如 `Z` 键）不放，光标周围出现一个圆形高清放大镜**，松开即恢复原状，看生肉极其顺手。   
- **继续阅读区改版为「并行阅读台」**
  - 你现在的首页顶部只有一条单行“继续阅读”（如截图里占了一整行的条状区域），对于经常同时追 2～3 本漫画的人来说利用率太低。可以改成**横向可滑动的 3～4 本“最近在读微缩卡带”**（带小封面 + 进度墨线），点一下直接秒进，既节省纵向空间又符合多线追漫习惯。   

### 二、 多书并行交互：把“多开软件”进化为“单窗分屏 / 标签页”

你在 3.1 计划里提到喜欢开 2～3 个实例同时看不同漫画来回切换（`U-20`）。双开进程虽然能用，但要在任务栏来回切窗口，而且容易出现状态保存覆盖。   

- **方案 A：阅读器顶部「轻量化多标签页」（最符合桌面直觉）**
  - 当你已经在看漫画 A 时，通过快捷键或返回书架打开漫画 B，顶部自动变成类似浏览器的紧凑标签栏（`[漫] 漫画A` | `[漫] 漫画B` | `+ 书架`），用 `Ctrl + Tab` 就能在两本书之间毫秒级切换，完全不需要启动多个软件进程。
- **方案 B：「左右对照分屏阅读」**
  - 针对生肉漫画或外文轻小说，允许把阅读区一分为二——左边放日文原版漫画/EPUB，右边放汉化版或 TXT 译文，甚至支持**双屏同步翻页锁定**。
- **保留多开捷径**：如果依然喜欢独立窗口（比如双显示器一屏放一本），在书卡右键菜单里加一个“在新窗口中打开”，省去手动去桌面重新点图标启动的麻烦。

### 三、 「纸墨」触感与仪式感：让软件有“翻开实体书”的呼吸感

既然确立了“碳墨刊头 / 纸墨”的独特审美，在动效和界面层次上可以做克制但惊艳的物理隐喻：   

- **书架「实体书脊 + 桌面光影」**
  - 给书卡封面左侧加上一道细腻的**装订压痕高光与微阴影**，右侧露出一道 **3px 浅米色纸张切口**；鼠标悬停时书本微微抬起 `4px`，阴影柔和扩散，保留你现有的 2px 进度墨线，既不油腻又有强烈的印刷品质感。   
- **开书「封面展开转场」与翻页「纸页折影」**
  - 结合你 3.1 的开书过场（`U-7a`），点击某本书时，让书卡封面平滑放大并淡出过渡为阅读正文，消除生硬的页面跳变；翻页时用纯 CSS `perspective` + 动态折痕阴影，让每一页翻动都像纸张掠过桌面投下微光。   
- **桌面级「阅读统计与日历热力图」**
  - 你底层已经统计了每本书的阅读时长，可以在独立设置页或单独的“阅读手账”视图里，用碳墨风做一个**极简像素热力图（类似 GitHub 绿格子，但用墨色深浅表示每日阅读分钟数）**，记录你读完了多少本漫画和小说，成就感拉满。   

### 四、 藏书私密性与“本地-云端”无感追更闭环

观察你的实际使用场景，还有两个非常接地气的痛点值得产品化：

- **「私密书架（隐身模式）」与「老板键」**
  - 个人本地书库里难免会有一些私人珍藏分类（比如你截图侧栏里的特定书架），当朋友在旁边、或者需要截图分享书库时，直接暴露在侧栏里会很尴尬。   
  - **设计方案**：允许将任意书架设为“私密书架”**——开启隐私保护后，该书架及其内部书籍会**从侧栏、全部藏书列表、全局搜索和继续阅读中彻底隐身，只有按下特定组合键（如 `Ctrl + Shift + H`）并验证密码后才会显现；同时提供一个全局“老板键”，一键瞬间隐藏窗口或伪装成空白阅读页。
- **wenku8 本地书架「原地追更」**
  - 目前拉取到本地的轻小说已经记录了 `wenku8_aid` 和最新章节 ID，但还得切到“云书架”标签页才能看到“有新章”。   
  - **设计方案**：在本地书架的书卡上直接显示一个极简的“更新”小墨点，右键书卡就能直接点“增量拉取最新章节”，后台静默把新章节追加进本地 EPUB，连云书架页面都不用点进去。

这四个方向里，哪一块最戳中你平时自己用这个软件时的痒点（比如**漫画连读与放大镜**、**多标签/分屏看书**、**纸墨物理动效**，还是**私密书架/原地追更**）？我们可以挑你最感兴趣的 1～2 个点，一起把具体的交互流程和界面布局推演细化。





把视野完全拉开，不纠结具体怎么写代码，我们先从**产品版图的横向延展**和**漫画在线源的接入路线**两个维度做一次全方位的发散。

### 一、 产品版图的横向延伸：你的阅读器还能长出哪些新器官？

你现在的 3.1 版本已经把“本地存储 + 格式兼容 + 基础阅读”打通了。如果往周边扩圈，有六个完全不同的产品方向可以拓荒：   

1. **生肉与外文「AI 伴读工作台」**
   - **漫画气泡 OCR + 悬浮译文**：针对你书库里大量的日文生肉漫画，接入轻量本地 OCR 或多模态视觉模型，鼠标划选漫画对白气泡，直接在旁边浮出翻译与语法拆解，不破坏画面。
   - **小说人物关系图谱与前情提要**：长篇轻小说动辄十几卷，隔半年再看经常忘掉配角是谁。选中人名一键唤出“该角色在本书前几章出现过的关键片段摘要”，或者根据当前已读进度自动生成“防剧透前情回顾”。
2. **「跨设备无缝接力」与局域网快传**
   - **零服务器云同步**：不自建昂贵后端，直接支持绑定 **WebDAV（坚果云 / Alist）或 OneDrive**，自动同步书库目录、阅读进度、划线笔记和标签。
   - **手机扫一扫“隔空投书 / 接力阅读”**：在软件里生成一个局域网二维码，手机微信或浏览器扫码就能把手机里的电子书/漫画压缩包无线甩进电脑书库；或者出门前点一下“发送到手机”，直接把当前在看的这一卷连同阅读进度推送到手机浏览器继续看。
3. **漫画专属「画质增强与裁边工坊」**
   - **老旧扫描版漫画实时超分 / 去网纹**：很多老漫画分辨率低、发黄有噪点，可以在渲染管线里加入轻量的实时锐化、自动对比度增强（让黑白线稿更黑、纸底更白）和去网纹滤镜。
   - **智能白边裁剪**：很多 PDF 或扫图漫画四周带着巨大的白边或扫描黑框，导致双页拼在一起中间隔了一条大白带。增加“自动裁切四周白边”开关，能让双页跨页图真正严丝合缝。
4. **「沉浸式氛围系统」与白噪音**
   - 既然主打「碳墨/纸墨」的阅读仪式感，可以内置极简的**环境白噪音混音器**（雨声、壁炉噼啪声、深夜图书馆翻书声、咖啡馆低语），看书时一键开启；配合**番茄钟/护眼提醒**（连续看漫画满 45 分钟，屏幕边缘出现温和的纸墨呼吸提示）。   
5. **「知识卡片化」与笔记生态联动**
   - 你目前已经支持划线高亮和导出 Markdown。再往前一步，可以让用户把金句一键生成「碳墨印刷风」高颜值分享长图（自动带书名、作者、二维码），或者直接一键同步到 **Notion / Obsidian / 思源笔记** 的指定双链库里。   
6. **书库「自动化流水线（Rules Engine）」**
   - 像邮箱过滤规则一样管理海量藏书：例如设定规则——*“凡是拖入的文件夹名包含 `[汉化]` 且页数 > 20 页，自动清洗标题、按 `[作者]` 打标签、自动归入 `漫画` 书架，并自动删掉压缩包里的宣传图（如 `招募.jpg` / `二维码.png`）”*。

### 二、 像 wenku8 一样走 API 连接的漫画源与协议推荐

想把在线漫画像 `wenku8` 那样直接拉取进本地书库，在工程上有**三条成熟路线**，各有优劣：   

#### 路线 1：拥有官方原生开放 REST API 的平台（最像 wenku8，最稳定）

这类平台直接提供公开文档和 JSON 接口，不需要破解网页，Rust 后端发 HTTP 请求就能直接拿到封面、目录和高清图片直链：

- **MangaDex API（`api.mangadex.org`）—— 全球漫画 API 的天花板**
  - **特点**：完全公开、文档极其规范的 RESTful API，无需爬网页、无复杂反爬加密。搜索、拉取封面、获取章节列表、拉取每一页的高清图片 URL 全都是标准 JSON 响应。
  - **资源覆盖**：海量日漫生肉、英译版以及非常丰富的简/繁中文汉化组发布，支持按语言代码（`zh` / `zh-hk` / `ja`）精准过滤，工程接入体验和 `wenku8` 几乎一模一样。
- **AniList API（GraphQL） / Bangumi API（`api.bgm.tv`）—— 专职元数据刮削**
  - **特点**：这两个不提供漫画图源下载，但非常适合做“本地漫画自动刮削器”。你电脑里那近 300 本本地漫画，只要把清洗后的标题发给 Bangumi 或 AniList API，就能一键自动补全日文原名、原作作者、连载状态、高分评价、题材标签和高清官方封面。   

#### 路线 2：接入通用标准私有云协议（一次开发，通吃 NAS 与网盘）

很多重度漫画玩家不会只依赖单一网站，而是把几百 GB 漫画存放在自己的 NAS 或网盘里：

- **OPDS 协议（v1.2 / v2.0）与 Komga / Kavita REST API**
  - **特点**：**Komga** 和 **Kavita** 是目前海外与国内 NAS 玩家最主流的开源自建漫画/电子书服务器，它们都暴露了标准的 OPDS 订阅源和 REST API。你的软件只要支持输入一个服务器地址和账号，就能像连 `wenku8` 一样直接浏览远程书库、在线流式看漫或一键拉取 CBZ 到本地。
- **Alist / WebDAV 协议挂载**
  - **特点**：国内用户极其高频的玩法——用开源工具 Alist 把阿里云盘、夸克网盘、百度网盘聚合成一个标准的 WebDAV 接口。你的 Rust 后端只要接入 WebDAV 客户端，就能直接把网盘里的漫画文件夹当作本地云书架浏览和拉取。

#### 路线 3：架构级最优解——兼容开源社区的「图源插件协议」（不硬编码任何网站）

如果你希望连接国内常见的在线漫画站（如拷贝漫画 CopyManga、哔哩哔哩漫画等），**千万不要在 Rust 代码里把某个具体漫画站写死**——因为这类网站域名经常变动、图片常带分块混淆加密（需要按特定算法重组画布），硬编码进去会让你陷入无休止的维护。

最聪明的做法是**借鉴你已经在 `README.md` 里参考过的 `legado（开源阅读）` 思路**，或者目前跨平台漫画界最火的开源项目 **Venera** / **Mihon（原 Tachiyomi）** 的图源规范：   

- **Venera 轻量 JS 图源规范**：Venera 允许用几十行标准 JavaScript 定义一个网站的“搜索 → 详情 → 章节 → 图片解密”链路，GitHub 上有大量现成的中文漫画源仓库（涵盖拷贝漫画等主流站点）。
- **你的切入点**：你不需要从零造轮子，只要让你的应用支持**导入标准化的 JSON/JS 图源规则文件**，把“解析规则”交给社区现成的插件库，你的软件依然保持纯粹、干净、无版权风险，同时又能一键连接全网几十个漫画站。

上面这些方向里，你觉得哪一类（比如 **MangaDex 原生 API 接入**、**Bangumi 本地漫画自动刮削**、**WebDAV/Alist 网盘直连**，还是 **局域网手机传书 / 规则自动化**）最符合你接下来想往产品里装的下一块拼图？





这一轮筛选非常果断——砍掉 AI OCR 和复杂笔记导出，能保住你现在最核心的竞争力：**极致的启动与翻页流畅度**（你在 v2.5 已经把条漫滚动压到 6.2ms、翻页掉帧压到 12ms 以内，这是重型阅读器很难做到的优势）。   

针对你对各个方向的疑问和顾虑，我逐一给你把底牌和更优解摊开：

### 一、 漫画在线源：为什么直接看「路线 3（图源插件）」才是最佳解？

你对 **路线 1（MangaDex / Bangumi）** 的顾虑非常准确，它们的真实定位是这样的：

- **MangaDex**：它是全球最大的免费多语言漫画站，日漫生肉和英译版极全，也有不少汉化组作品，而且是唯一提供**官方公开免费 API**、永远不会突然改版防爬虫的平台。**但它的短板很明显**：国产漫画、韩漫中文版偏少，很多国内汉化组只发国内站点，且国内直连需要走代理。
- **Bangumi（番组计划）**：它**不提供漫画图片下载**，它是国内二次元最全的条目数据库。它唯一的用途是做“本地元数据刮削”——当你导入一本文件名乱七八糟的本地漫画时，发请求给它，自动帮你补全准确的中文译名、作者、连载状态和高清官方封面。

**那国内看漫“资源最全、查询最方便”的方案是什么？—— 就是你保留的「路线 3（社区图源插件协议）」**。

国内资源最全的漫画站（如拷贝漫画、包子漫画、哔咔、禁漫等）没有任何一家提供公开 API，而且域名频繁更换、图片常带分块混淆加密（需要按特定算法重组画布）。如果硬写死在你的 Rust 代码里，每隔几周网站一改版你就得重新编译发版。

- **成熟做法**：借鉴你之前参考过的 `legado（开源阅读）` 或目前跨平台漫画界最火的开源项目 **Venera** 的思路——主程序只提供一个**轻量 JS/JSON 规则解释器**。GitHub 上有大量现成的中文漫画源仓库，导入规则文件后，搜索、目录、图片解密拉取全部由规则驱动，全网主流漫画站都能搜到，且主程序永远干净无维护负担。   

### 二、 针对你保留项目的可行性与避坑解答

#### 1. 画质增强与智能裁边：如何做到“绝对不卡翻页”？

你目前已经有“前后几页图片内存预加载”机制，只要选对技术路径，画质增强**完全不会拖慢翻页**：   

- **调色/对比度/锐化（走显卡 GPU 实时滤镜，零开销）**：让老旧扫描漫画“黑线更黑、黄底变白”，**不需要重新生成图片文件**，直接利用浏览器显卡硬件加速的滤镜实时叠在渲染层上——内存零增加，开关秒切换，翻页依然是 12ms 级瞬开。   
- **自动裁切四周白边/扫描黑框（算坐标，不改原图）**：在后台预加载下一页图片时，顺手用极简算法扫描出上下左右的白边像素边界，渲染时直接按裁剪后的视野展示，既省硬盘空间又不阻塞主线程。

#### 2. 手机接力阅读与跨平台同步：避开网盘封禁的轻量化设计

既然没有 NAS，国内网盘又容易和谐漫画资源，最适合你的有两条**零成本、零审查风险**的路线：

- **局域网「手机扫码秒读」（不传文件，直接串流）**：电脑端 BookReading 开放一个本地局域网端口，手机只要在同一个 Wi-Fi 下扫一下二维码，用手机浏览器就能直接看电脑书库里的漫画和小说，阅读进度实时写回电脑的 SQLite 数据库；出门前也可以一键把当前这一卷推送到手机浏览器离线缓存。   
- **「纯进度/书单」轻量云同步（不传漫画大图）**：漫画文件动辄几百 MB，云同步最慢也最容易被封；但**阅读进度、书签、标签、书架结构**加起来还不到几百 KB（纯结构化数据）。绑定一个免费 WebDAV（如坚果云）或 GitHub 私有仓库，只同步进度和书单，永远不会触发网盘审查，还能为未来做 Tauri 2 手机端铺路。   

#### 3. 书库自动化规则（优化你觉得“不太好”的现有功能）

你目前已经有了 `[作者] 标题` 拆分和八步标题清洗管线，之所以用起来还觉得别扭，通常是因为**规则太死板、缺“试运行预览”**，以及**漫画压缩包里常夹杂广告图**。   

- **升级方向**：
  - **可视化条件规则**：允许你自己配置 `当文件夹名/标签包含 [关键词] 时 -> 自动归入 [指定书架] + 自动打上 [指定标签]`，执行前先展示一份“预计变动预览表”，确认再落库。   
  - **漫画“净版过滤”**：导入或阅读漫画时，自动识别并隐藏汉化组夹带的**招募广告页、二维码页、跳转提示图**（通常这类图片尺寸比例异常或文件名带特定后缀），阅读体验会清爽很多。

### 三、 减法之后，你的「BookReading」产品版图已经非常清晰

经过这一轮大浪淘沙，你的软件不再是一个臃肿的四不像，而是聚焦在四个极其纯粹的核心支柱上：

1. **极致轻快的本地阅读内核**：碳墨/纸墨高颜值界面 + 零开销 GPU 画质增强/自动裁边 + 沉浸白噪音与护眼节奏。   
2. **懂重度藏书者的智能书库**：可视化自动整理规则 + 漫画广告页自动过滤 + 私密书架隐身保护。
3. **开放插件化的云端书架**：延续 `wenku8` 的整本拉取与追更体验，通过社区 JS 图源插件横向打通全网在线漫画站。   
4. **无感跨端接力**：局域网手机扫码串流阅读 + 纯进度/标签轻量云同步。

### v3.2：UI 组件底座与「重度追漫」体验跃迁

**核心逻辑**：你在 `开发计划-v3.1.md` 中已规划好 `F-1`（无样式组件基座）和 `F-6`（独立设置大页面）。这一步必须最先落地——因为后面所有的画质滤镜、自动化规则、图源插件都需要一个宽敞、规整的“设置中心”来安放开关，否则弹窗会彻底塞不下。同时，把最高频的漫画痛点和“碳墨”物理质感一并交付。   

1. **工程与布局底座（延续原定规划）**
   - **无样式组件层 + 窄窗自适应（`F-1` + `F-8`）**：引入 Radix 类 headless 基座接管键盘焦点与下拉菜单行为，保持「碳墨」皮肤不变；落地 `<800px` 图标化侧栏与图标唤起式搜索框。   
   - **独立设置大页面（`F-6`）**：告别拥挤浮窗，建立左侧分区导航（外观 / 阅读 / 漫画增强 / 书库规则 / 网络更新）的独立路由页面。   
2. **重度漫画阅读工作台（高价值刚需）**
   - **系列卷叠放 & 无缝连读下一卷**：同系列多卷漫画在书架自动折叠成带“叠层厚度”的系列卡；读到第 1 卷末页继续翻页时，底部浮出轻提示一键无缝进入第 2 卷，无需退回书架。
   - **日漫生肉「局部放大镜（Loupe）」**：按住鼠标中键或快捷键（如 `Z` 键），光标周围出现圆形高清放大镜查看小字假名，松开即还原，省去整页缩放再拖拽的繁琐。   
   - **零开销 GPU 画质增强 & 智能裁边**：利用显卡实时滤镜实现老旧扫图锐化、黑线加深与黄底漂白（不改原图、不占额外内存，保住 12ms 级翻页速度）；后台预加载时顺带计算白边坐标，自动裁切扫描黑框/白边，让双页跨页图无缝拼接。   
3. **「纸墨」物理触感升级（延续 `U-7b`）**
   - **书架微拟物书脊**：为封面增加 1px 装订压痕高光与 3px 纸张切口边缘，悬停微浮起，保留现有 2px 进度墨线。   
   - **纯 CSS「纸页折影」仿真翻页**：利用 CSS 3D 透视与动态折痕阴影模拟纸张掀开效果（单双栏自适应中缝轴），并与现有 150–600ms 速度滑块联动。   

### v3.3：藏书自动化、私密空间与多书并行

**核心逻辑**：在 v3.1 的标题清洗 v2（`U-4`） 跑通后，进一步把“人工整理 300+ 本漫画”变成全自动流水线，同时解决你目前靠“多开软件进程（`U-20`）”看多本漫画的痛点。   

1. **可视化自动化规则引擎（`F-3` 升级）+ 漫画净版过滤**
   - **条件动作流**：支持配置 `当文件夹名/标题包含 [关键词] 时 -> 自动归入 [指定书架] + 按 [作者] 自动打标`，执行前提供“预计变动预览表”，确认后批量落库。   
   - **漫画广告页自动过滤**：导入或阅读时自动识别汉化组夹带的招募页、二维码页、跳转提示图并自动隐藏（支持手动恢复显示），让连贯阅读不被打断。
2. **「私密书架」与「老板键」**
   - **隐身书架模式**：支持将特定敏感分类设为“私密书架”，开启隐身后该书架及其内部书籍从侧栏、全部藏书、全局搜索和继续阅读中彻底消失；仅在输入特定快捷键（如 `Ctrl + Shift + H`）并验证密码后显现。
   - **全局老板键**：一键瞬间隐藏窗口或切换为纯白/经典名著伪装阅读界面。
3. **单窗多书并行流 & wenku8 原地追更**
   - **阅读器轻量化多标签页 + 分屏**：打开多本书时顶部出现紧凑标签栏（支持 `Ctrl + Tab` 秒切），并支持“左右分屏对照”（适合生肉漫画与译文文本同屏对照翻页）；同时在书卡右键保留“在新窗口中打开”。   
   - **并行阅读台**：将首页单条“继续阅读”升级为横向 3～4 本“最近在读微缩卡带”，满足多线追漫。   
   - **wenku8 本地原地追更**：在本地书架的轻小说书卡上直接显示“有新章”墨点，右键即可后台静默增量拉取最新章节入库，无需切去云书架页面。   
4. **沉浸式白噪音与护眼节律**
   - 内置极简白噪音混音器（雨声、壁炉、翻书声）与温和的番茄钟护眼呼吸提示。

### v3.4：开放漫画图源生态（社区插件化追漫）

**核心逻辑**：等 v3.2 的设置大页面和 v3.3 的自动洗名/去广告管线全部就绪后，再引入外部在线漫画源，下载下来的漫画就能直接享受全套自动化整理。   

1. **轻量 JS/JSON 图源规则解释器**
   - 借鉴 `legado` 与 `Venera` 的社区插件思路，主程序不硬编码任何具体漫画网站，而是提供标准化的规则运行沙盒（支持网页请求、JSON 解析及常见的漫画图片分块反混淆重组）。   
   - 用户可直接导入 GitHub 社区维护的现成中文漫画源规则文件（覆盖拷贝漫画等主流站点），彻底免除网站频繁改版带来的主程序维护成本。
2. **统一搜漫与一键拉取入库**
   - 复用 `wenku8` 云书架已验证成功的交互模型：聚合搜索多图源 → 查看简介/卷章目录 → 选择本地目标书架 → 并发下载整卷并自动打包为本地 CBZ 入库，同时自动触发 v3.3 的广告页过滤与标题清洗。   

### v3.5：无感跨端接力与轻量云同步

**核心逻辑**：作为体验闭环的最后一环，避开国内网盘对漫画大文件的审查封禁，用最轻量的方案解决“离开电脑桌后在床上用手机继续看”的场景。

1. **局域网「手机扫码秒读」（零文件传输串流）**
   - Rust 后端内置轻量局域网 HTTP 服务，电脑端点击“手机接力”弹出二维码；手机连同一 Wi-Fi 扫码后，直接在手机浏览器打开适配触屏的条漫/小说阅读页，实时读取电脑书库图片并把阅读进度写回电脑 SQLite 数据库。   
   - 支持“一键缓存本卷到手机”，方便出门前离线带走单卷阅读。
2. **纯结构化数据轻量云同步**
   - 只同步**阅读进度、书签、标签、书架目录与自动规则**（纯文本配置，体积仅几百 KB，永远不触碰网盘敏感内容审查），支持绑定坚果云 WebDAV 或个人私有 GitHub 仓库；同时为未来基于 Tauri 2 构建独立的移动端阅读 App 预留好统一的数据契约。
