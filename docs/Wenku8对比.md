# BookReading × Wenku8_Flutter 对比

> 对象：[mikufoxxx/Wenku8_Flutter](https://github.com/mikufoxxx/Wenku8_Flutter)（1929★，Dart/Flutter，GPL-3.0，v0.5.6+2277，2026-11 仍活跃）
> 重要前提：该仓库是**部分实现的公开快照**——官方声明不能独立构建，wenku8 在线源/听书增强/LAN 传输等模块在公开代码中为空桩或缺失（README_ZH.md:130-134）。下述涉及其"在线侧"的能力均来自其文档宣称，源码未证实。
> 本方参照：`docs/功能清单.md`（v2.5.x）。测绘快照：2026-11-08。

## 0. 一句话定位

| | BookReading | Wenku8_Flutter |
|---|---|---|
| 平台 | Windows 桌面（Tauri2 + WebView2） | Android / iOS / 鸿蒙（Flutter 三端） |
| 内容来源 | **纯本地库**（导入什么读什么） | wenku8 轻小说在线源 + 本地书 |
| 强项 | 漫画/视觉书体验、本地库管理、性能 | 轻小说排版深度、听书、阅读报告、三端 |

两者交集是"本地书阅读器"，但产品形态不同：它是**移动端轻小说客户端**（在线为主、本地为辅），我们是**桌面端全格式本地书库**（四格式含漫画，无任何在线源）。

## 1. 架构与存储

| 维度 | BookReading | Wenku8_Flutter |
|---|---|---|
| 渲染 | epub.js(iframe) + pdf.js + 原生 img 管线 | **纯自绘**（TextPainter 逐行分页，0 WebView，竖排 tategaki） |
| 存储 | SQLite（WAL+索引，托管连接） | **无 sqlite**——SharedPreferences(JSON)+文件；EPUB mmap 直读原文件不复制 |
| 后端 | Rust（异步命令、缩略图管线、trash 删除） | Dart + 原生插件层（Kotlin/Swift/ArkTS 三套）+ C 引擎（libmobi） |
| 规模 | 前端 ~3 万行 TS + Rust ~5 千行 | **298 个 dart 文件 / 11.6 万行** + 三端原生 ~100 文件 |
| 测试 | **162 前端 + 97 Rust 用例全绿** | **0**（无 test/ 目录） |
| 许可 | MIT | GPL-3.0（代码不可借用，只可借鉴思路） |

## 2. 格式支持

| 格式 | BookReading | Wenku8_Flutter |
|---|---|---|
| EPUB | ✅ epub.js（注音/注释支持一般） | ✅ 自研解析（**保留注音 ruby、注释、混合横竖排**，拒 DRM） |
| TXT | ✅ 编码探测 + legado 规则池分章 | ✅ 卷/章正则 + GB18030/Big5/UTF-16 |
| 漫画（文件夹/CBZ/webtoon/RTL/双页/缩放/自动滚动） | ✅ **完整** | ❌ 无 |
| 图片型 PDF | ✅ 按漫画交互 | △ PDFBox 转文本向 EPUB（重排版，非原样阅读） |
| MOBI/AZW/AZW3/PRC | ❌（P2，纯 Rust 无解） | ✅ **libmobi C 引擎解包→重建 EPUB**（不解 DRM） |
| FB2/DOC/DOCX/RTF/HTML/Markdown | ❌ | ✅ 原生桥转换（POI/PDFBox/jsoup/commonmark） |
| 批量 | ✅ 父目录扫描 + 查重 + 补副本 | ✅ + 同系列分卷合并 + 网盘导入 |

**对我们的启示**：mobi/azw3 这条 P2 有现成路——FFI 挂 libmobi（LGPL，动态链接）解包成 OEBPS 再走现有 EPUB 管线，WenkuBookEngine 已验证可行性。

## 4. 独有于对方的能力（我们完全没有）

1. **TTS 听书**：三音源（Edge 在线协议自实现 / 系统 TTS / 自定义 SSML）、倍速、段落跟随高亮、双语自动切音色、后台锁屏耳机控制、睡眠定时
2. **阅读报告**：8 套版式图片导出、阅读纪念/四季插图、**触摸指纹热图**、五维统计页
3. **三端原生桌面小组件**：内容 5 ×样式 5 ×尺寸 3 ×明暗
4. **局域网续读**：同 Wi-Fi 发现+六位码配对，传书/传位置（快照缺实现）
5. **云同步**：.wenku8sync 手动合并（S3/WebDAV/夸克；Dart 自实现 SigV4）——注意非端到端加密
6. **离线词典**：MDict/StarDict/Kindle 词典点击查词
7. **竖排与混合横竖排**
8. 在线源生态：账号/云书架/签到/评论/离线缓存（快照空桩）

## 5. 独有于我们的能力（对方没有）

1. **漫画阅读全套**：webtoon 连续滚动、RTL、单双页+宽页跨页+双页偏移、0.5–4x 锚点缩放、条漫自动滚动+调速、按显示尺寸降采样
2. **视觉书管线**：页元数据占位、zip 句柄缓存、缩略档、content-visibility——大书架/长条漫性能实测数据（jank 11→0）
3. 深桌面集成：系统托盘、窗口状态记忆、F11、真删除到 Windows 回收站
4. SQLite 数据层（WAL/索引/批量迁移）——书量增长的基础
5. 八主题 × 壳/弹窗/正文三处同步 + 全局背景图双层纱
6. 阅读时长统计与 Markdown 导出（对方报告花哨但无导出文本）
7. **162+97 测试全绿的工程纪律**（对方 0 测试 + 公开快照不可构建）

## 7. 结论

- **不要对标它的在线侧**：wenku8 源与其账号体系是它的产品根基，且公开代码里根本没有；我们的定位是本地库。
- **值得抄作业的三件套**：libmobi 打通 mobi/azw3、排版细项+按书范围、词典查词——全部服务"本地读得更舒服"。
- **我们的护城河**：漫画/视觉书体验（它完全没有）+ 桌面级性能与数据层 + 测试纪律。
- 它 11.6 万行 0 测试、无 sqlite、快照不可构建；工程稳健性我们占优，产品打磨（听书/报告/排版深度）它占优——选择性吸收即可。
